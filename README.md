# tcg-restock-notifier

トレーディングカードの抽選受付開始・即時購入の在庫復活を検知して Discord に通知するツール。
5分おきに GitHub Actions が対象ページをチェックし、変化があれば Discord Webhook 経由で通知します。
状態(`state.json`)はリポジトリにコミットされるため、通知先が Discord アカウントである限り、iPhone の機種変更・故障があっても引き継ぎ不要です。

## セットアップ

1. **Discord Webhook を作る**
   Discord サーバー → 通知を受け取りたいチャンネルの設定 → 連携サービス → ウェブフック → 新しいウェブフック → URLをコピー。

2. **GitHub リポジトリを作る**
   このフォルダの中身を新規リポジトリに push する。

   ```
   git init
   git add .
   git commit -m "init"
   git branch -M main
   git remote add origin <あなたのリポジトリURL>
   git push -u origin main
   ```

3. **Secrets を登録**
   リポジトリの Settings → Secrets and variables → Actions → New repository secret
   - Name: `DISCORD_WEBHOOK_URL`
   - Value: 手順1でコピーしたURL

4. **Actions を有効化**
   Actions タブで workflow を確認し、`Run workflow` で手動実行して動作確認する。以降は5分おきに自動実行されます。

## 監視対象の追加・変更

`targets.yaml` にエントリを追記するだけです。

```yaml
- name: "わかりやすい名前"
  url: "https://example.com/product/xxxx"
  keyword: "SOLD OUT"
  alert_on: "disappear"   # キーワードが消えたら通知(売り切れ表示が消えた=買える)
```

- `alert_on: "appear"` → キーワードが新しく出現したら通知(例: 「抽選受付中」の文字が出た)
- `alert_on: "disappear"` → キーワードが消えたら通知(例: 「SOLD OUT」の文字が消えた)

実際のページを見て、対象商品ページで在庫あり/なしがどんな文言で表示されるか確認し、`keyword` と `alert_on` を調整してください。

## 応募状況の管理・締切/当選発表リマインド

抽選まとめサイト(`lottery_list`タイプ)で新規検知した抽選は、スプレッドシートの Date シートに自動で1行追記されます。このとき「応募状況」列は**空欄のまま**追加されます(検知した抽選すべてに自動でリマインドが付くとスパムになるため)。

応募したい抽選だけ、スプレッドシート上で手動で以下のように入力してください。

- 応募するつもりのものに「応募状況」列を **`未応募`** にする → 締切の前日・当日になると、締切が近い「未応募」の**件数をまとめて**Discordにリマインドが届きます(1件でも複数件でも通知は1回)。あわせて、Googleカレンダー(`asxagpe1@gmail.com`のメインカレンダー)のその日に「未抽選が◯件あります」という終日の**予定**が自動作成・更新されます(件数が0件に戻ると自動で削除されます)
- 応募し終えたら **`応募済み`** に変更する → 当選発表日になると Discord にリマインドが届きます(「締切」列から自動抽出した日付、または説明文から抽出した「当選発表日」列を見ています)
- 結果が分かったら **`落選`** または **`当選`** に変更する → それ以上リマインドされません

リマインドは1日2回(朝8:20 JST / 夜23:00 JST、`.github/workflows/remind.yml`)実行され、`python remind.py` で手動実行もできます。当選発表リマインドは行ごとに1回ずつ送られ、「当選発表リマインド済」列に `TRUE` が入ることで重複送信を防いでいます。

締切・当選発表日の自動抽出がうまくいかない場合は、該当セルを直接手で修正してもらえれば、次回以降そのままリマインド判定に使われます。

カレンダー連携には、Google Calendar APIの有効化と、対象カレンダーをサービスアカウント(`GOOGLE_SERVICE_ACCOUNT_JSON`のメールアドレス)と共有(予定の変更権限)しておく必要があります。未設定でも他の機能には影響しません(カレンダー同期だけ静かにスキップされます)。

## 半自動応募(ローカル専用)

応募すると決めた抽選について、応募フォームを開いて氏名・住所などの入力までを自動化し、**送信は必ず自分で行う**ためのツールです。全自動送信は絶対に行いません。

1. `applicant.example.json` を `applicant.local.json` という名前でコピーする(`applicant.local.json` は `.gitignore` 済みなのでコミットされません)
2. `applicant.local.json` の中身をご自身の実際の情報(氏名・フリガナ・郵便番号・住所・電話番号・メールアドレス)に書き換えて保存する。**クレジットカード番号などの決済情報は絶対に入れないでください**(そもそも自動入力の対象外にしていますが、保存すること自体避けてください)
3. 応募したいページのURLを渡して実行する

```
python apply.py "https://example.com/apply-page"
```

- **Googleフォーム(`docs.google.com/forms/...` または `forms.gle/...`)の場合**: ブラウザは画面に表示せず(裏で構造を読み取るだけ)、氏名・住所などが**事前入力された状態のURL**を組み立てて、そのままDiscordに送ります。スマホなどどの端末からでもそのリンクを開けば入力済みの状態で表示され、その場で確認・送信できます。
- **それ以外(店舗独自のフォームなど)の場合**: ブラウザが画面に表示された状態(ヘッドレスではない)で起動し、テキスト・メール・電話番号・数値の入力欄だけを自動入力します。チェックボックス・ラジオボタン・セレクトボックスは一切操作しません。この場合は今実行しているPC上でしか下書きを確認できません。
- どちらの場合も、「カード番号」「CVV」「口座」など決済に関わるフィールドは、キーワードに関わらず自動入力の対象外です。
- どちらの場合も、**送信ボタンは一切押しません**。内容を確認のうえ、ご自身の判断で送信してください。
- 店舗ごとにフォームの作りが大きく異なるため、自動入力の精度は店舗によってばらつきます。うまく入らないフィールドはターミナル(独自フォームの場合)またはDiscordの通知(Googleフォームの場合)で件数が分かるので、そこだけ手で入力してください。
- 下書きを用意すると、渡したURLがスプレッドシートの「URL」列と一致する行を自動で探し、応募状況が空欄または`未応募`であれば **`下書き済み`** に更新します(まだ実際には送信していない状態を表します)。`下書き済み`は「未応募」と同じく締切リマインドの対象になりますが、当選発表リマインドの対象にはなりません(送信していないので発表を待つ意味がないため)。実際に送信したら、忘れずに`応募済み`へ手動で変更してください。

## ローカルでのテスト

```
pip install -r requirements.txt
$env:DISCORD_WEBHOOK_URL = "https://discord.com/api/webhooks/xxxx"
python check.py
```

## 既知の注意点

- WAF/Bot対策があるサイトは `targets.yaml` の対象に `render: true` を付けることで、最初からヘッドレスブラウザ(Playwright)で取得するようにできます。ポケモンセンターオンラインにはデフォルトで設定済みです。
- さらに、取得したHTMLが「Just a moment...」「Access Denied」のようなブロック/確認ページだった場合は、`requests`→Playwrightへの自動フォールバック、およびPlaywrightで取得した場合でも取得失敗として扱い、誤った内容で通知・状態更新をしないようにしています(`check.py` の `_looks_like_block_page`)。ただし文言はサイトごとに異なるため、新しいブロックページに遭遇したらマーカーを追加調整してください。
- Amazon・楽天などの大手ECモールはスクレイピングが利用規約に抵触しやすいため、意図的に対象外にしています。
